# Module 1 Project — EC2 + S3 with Terraform

## Starting point and purpose

This is the **first hands-on Terraform project** in the course. You start from an empty project directory and provision a minimal AWS environment in `us-east-1` using the **default VPC** so the focus stays on Terraform fundamentals rather than networking design.

**What you build:**

- An S3 bucket with public access blocked, versioning, and AES-256 encryption.
- A security group allowing HTTP from the internet and SSH from one trusted CIDR.
- A `t3.micro` EC2 instance running Apache HTTP Server via `user_data`.

**Learning goals:** provider configuration, variables, data sources, resources, outputs, and the init → plan → apply workflow.

---

## Architecture

```text
Internet
   |
   +-- HTTP :80 --> Security Group (web) --> EC2 (Apache)
   |
   +-- SSH :22 (trusted CIDR only)

S3 bucket (private, versioned, encrypted) — independent of EC2
```

## File index

| File | Purpose |
|------|---------|
| `versions.tf` | Pins Terraform `>= 1.6.0` and AWS provider `~> 5.0`. |
| `providers.tf` | Configures the AWS provider with default tags (Project, Environment, ManagedBy, Course, Module). |
| `variables.tf` | Declares inputs: region, project name, environment, bucket name, instance type, SSH CIDR, optional key pair. |
| `main.tf` | Core resources: data sources (VPC, subnets, AMI), S3 bucket + hardening, security group, EC2 instance. |
| `outputs.tf` | Exposes bucket name/ARN, instance ID, public IP, and `web_url` after apply. |
| `terraform.tfvars.example` | Example variable values — copy to `terraform.tfvars` and edit. |
| `.gitignore` | Ignores `.terraform/`, state files, private tfvars, and plan files. |
| `.terraform.lock.hcl` | Provider version lock file generated by `terraform init`. |

## Feature → file mapping

| Feature | Contributing files | Key resources |
|---------|-------------------|---------------|
| **Storage (S3)** | `main.tf` | `aws_s3_bucket.app`, public access block, encryption, versioning |
| **Compute (EC2)** | `main.tf` | `aws_instance.web`, AMI/VPC/subnet data sources, `user_data` |
| **Security / networking** | `main.tf` | `aws_security_group.web`; default VPC via data sources |
| **Configuration / wiring** | `variables.tf`, `providers.tf`, `versions.tf` | Inputs, tags, provider constraints |
| **Post-apply visibility** | `outputs.tf` | Bucket name, instance ID, `web_url` |

## Prerequisites

- Terraform 1.6 or newer.
- AWS credentials configured in your shell.
- Permission to manage EC2, security groups, and S3 in `us-east-1`.
- A globally unique S3 bucket name.

```bash
aws sts get-caller-identity
```

---

## Configure

```bash
cp terraform.tfvars.example terraform.tfvars
```

Edit `terraform.tfvars`:

```hcl
aws_region     = "us-east-1"
project_name   = "iac-fundamentals"
environment    = "dev"
bucket_name    = "your-unique-bucket-name-here"
instance_type  = "t3.micro"
ssh_cidr_block = "YOUR_PUBLIC_IP/32"
key_name       = null
```

Find your public IP: `curl https://checkip.amazonaws.com`

---

## Run

Single root — no multi-step dependency order.

```bash
terraform init
terraform fmt
terraform validate
terraform plan -out=tfplan
terraform apply tfplan
terraform output web_url
```

Allow one to two minutes for `user_data` to install Apache.

```bash
terraform destroy   # when finished
```

---

## State and Git warning

Local state files (`terraform.tfstate`) can contain sensitive metadata. Do not commit state or private `*.tfvars`. In production, use remote state (S3 + DynamoDB locking) as taught in Module 4.

---

## Troubleshooting

- **BucketAlreadyExists:** S3 names are globally unique — choose a different `bucket_name`.
- **InvalidKeyPair.NotFound:** Set `key_name = null` if you do not need SSH.
- **No default VPC:** Create a default VPC or adapt the code to use explicit VPC/subnet resources.
- **Web page does not load:** Wait for `user_data`, then verify security group port 80 and instance status checks.
